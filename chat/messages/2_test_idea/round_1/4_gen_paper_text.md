HOWP generates synthetic worlds to probe ambiguous scope/negation distinctions and requires an LLM oracle because NL truth in abstract worlds is not deterministic.\\n\\n**Self-Consistency.** Wang et al. [14] propose sampling k reasoning chains and selecting by majority vote. We adapt this to NL-to-FOL as a baseline: cluster k=5 translations by Jaccard similarity and pick the largest-cluster centroid. Our method extends this by incorporating model-theoretic world evidence rather than surface-level translation agreement.\\n\\n**Ensemble Theory.** Breiman [8] showed that ensemble diversity—not just size—determines generalization. Lakshminarayanan et al. [9] derive uncertainty estimation power from parameter-space independence in deep ensembles. HOWP imports this principle to motivate heterogeneous oracle design.\\n\\n# Method\\n\\n## Problem Formulation\\n\\nGiven an NL sentence $S$ (a premise or conclusion from FOLIO [15]), a candidate generator produces $k$ FOL candidate translations $\\\\{F_1, \\\\ldots, F_k\\\\}$. The goal is to select the candidate $F^*$ with highest semantic faithfulness to $S$ without access to gold FOL annotations. Faithfulness is operationalized as *downstream inference accuracy*: whether substituting $F^*$ into the full FOLIO problem (premise set + conclusion) and running Z3 [16] produces the correct entailment/contradiction/neutral verdict.\\n\\n## Pipeline Overview\\n\\nHOWP proceeds in four phases, illustrated in Figure 1.\\n\\n**Phase 0 — Beam Recall Gate.** Before running the full pipeline, we measure oracle upper bound: for 50 FOLIO validation examples, generate k=5 candidates with the generator LLM and check whether *any* candidate produces the correct Z3 verdict on the FOLIO problem. This bounds the maximum accuracy achievable by any selection strategy.\\n\\n**Phase 1 — Oracle Calibration Pilot.** On 30 hand-constructed (sentence, world, truth-value) triples spanning three categories—simple predication (A), explicit negation (B), and quantifier scope ambiguity (C)—we measure the oracle LLM's binary truth-judgment accuracy against human ground truth. This validates that the oracle provides a discriminative signal.\\n\\n**Phase 2 — Main Heterogeneous-Oracle Pipeline.** For each of the 204 main-experiment FOLIO examples:\\n1. Generate $k=5$ FOL candidate translations using Llama-3.1-8B [17] with 5-shot prompting in NLTK logic module syntax.\\n2. Apply syntactic pre-filter: exclude candidates where open-domain existential quantifiers without named witnesses would invalidate the closed-world assumption (0.5% filter rate).\\n3. Generate $m=8$ *diagnostic world models* using Qwen2.5-7B-Instruct [18]: each world is a minimal finite structure over 3–7 explicitly named domain elements, with ground atoms chosen to discriminate between competing semantic interpretations of $S$.\\n4. Evaluate each candidate $F_i$ in each world $W_j$ using the deterministic Python FOL model checker [ARTIFACT:art_KBu-e9nf2SfO], yielding a binary truth value $\\\\text{checker}(F_i, W_j) \\\\in \\\\{0,1\\\\}$.\\n5. Query Qwen2.5-7B-Instruct for oracle judgment $\\\\text{oracle}(S, W_j) \\\\in \\\\{0,1\\\\}$ for each world.\\n6. Compute cross-world agreement score: $\\\\text{score}(F_i) = \\\\frac{1}{m}\\\\sum_j \\\\mathbf{1}[\\\\text{checker}(F_i, W_j) = \\\\text{oracle}(S, W_j)]$.\\n7. Select $F^* = \\\\arg\\\\max_i \\\\text{score}(F_i)$, breaking ties by generation order.\\n\\n**Phase 3 — Baselines and Ablations.** All conditions evaluate via Z3-based downstream accuracy. Baselines: (i) *top-1*: take the first generated candidate; (ii) *self-consistency*: cluster k=5 translations by Jaccard character n-gram similarity, select centroid of largest cluster; (iii) *direct-judge*: ask Qwen2.5-7B to select the best formula directly without world models. Ablations: (A) *same-model oracle*: use Llama-3.1-8B for both generation and oracle judgment; (B) *random worlds*: replace diagnostic world generation with randomly sampled ground-atom combinations; (C) $m=4$ worlds: reduce world count from 8 to 4.\\n\\n## Symbolic FOL Model Checker\\n\\nThe deterministic model checker [ARTIFACT:art_KBu-e9nf2SfO] implements a recursive evaluator over finite named worlds. A world is represented as `{'domain': list[str], 'atoms': dict[str, bool]}`. Quantifiers iterate over explicitly listed domain elements under the closed-world assumption: existential quantifiers check if any domain element satisfies the body; universal quantifiers check all elements. The checker handles NLTK logic module syntax (`all x. (P(x) -> Q(x))`, `exists x. (P(x) & Q(x))`, negation `-`, conjunction `&`) and runs in milliseconds for formulas with $\\\\leq$3 quantifiers over domains of $\\\\leq$10 entities. The Z3 solver [16] is used separately for final downstream inference evaluation.\\n\\n## Implementation Details\\n\\nAll LLM calls use the OpenRouter API. Generator: `meta-llama/llama-3.1-8b-instruct` at \\\\$0.02/\\\\$0.03 per 1M input/output tokens. Oracle: `qwen/qwen-2.5-7b-instruct` at \\\\$0.04/\\\\$0.10 per 1M input/output tokens. The pipeline uses a hard cost-halt at \\\\$8.50, with final total cost of \\\\$0.43. Concurrent API calls use `ThreadPoolExecutor` with automatic retry on rate-limit errors.\\n\\n# Experiments\\n\\n## Dataset\\n\\nWe use the FOLIO benchmark [15] [ARTIFACT:art_9o087KJ7Hcj0], a 1,430-example NL reasoning dataset with gold FOL annotations. We evaluate on the validation split (203 examples). The main experiment uses a stratified sample of 204 examples balanced across entailment/contradiction/neutral labels (84/84/84 approximate targets) and quantifier complexity tiers (0/1/2+ quantifiers). The beam-recall analysis uses 50 held-out validation examples; the oracle pilot uses 30 hand-constructed sentence-world pairs.\\n\\n## Phase 0: Beam Recall Analysis\\n\\nOn 50 FOLIO examples, Llama-3.1-8B with k=5 candidates achieves **38% beam recall**—that is, at least one of the five candidates produces the correct Z3 verdict for only 38% of examples. This falls substantially below the 60% pre-specified gate. Proceeding despite this threshold violation is instructive: the 38% oracle upper bound means that no selection strategy, however perfect its discriminative signal, can exceed 38% accuracy. The observed overall accuracies (19.6%–24.5%) are consistent with random-or-better selection within this constrained beam.\\n\\n## Phase 1: Oracle Calibration\\n\\nOn 30 (sentence, world, truth-value) triples, Qwen2.5-7B-Instruct achieves **76.7% agreement with human ground truth**, passing the ≥72% gate. Performance is uneven across categories: the oracle is most accurate on simple predication (category A) and least accurate on quantifier scope (category C), which involves implicit scope ordering that requires careful disambiguation.\\n\\n## Phase 2: Main Pipeline Results\\n\\nTable 1 summarizes accuracy for all seven conditions on 204 FOLIO examples.\\n\\n[FIGURE:fig_results]\\n\\nThe heterogeneous-oracle main method achieves **20.6%** accuracy (95% CI: [15.0%, 26.1%]). This is statistically indistinguishable from top-1 generation (19.6%) and self-consistency (20.6%). The direct-judge baseline (20.1%) is similarly indistinguishable. No pairwise difference among the four primary conditions exceeds 1.0 percentage point, and all confidence intervals substantially overlap.\\n\\nAccuracy by label exhibits large variance: Uncertain 36.2%, Entailment 13.9%, Contradiction 11.1%. The higher accuracy on the Uncertain class reflects that many examples without a clear logical relationship receive a default Uncertain prediction—a partial coincidence of prediction and label rather than a principled inference.\\n\\n## Phase 3: Ablations\\n\\nThree ablations probe the contribution of specific design choices.\\n\\n**Ablation A (Same-Model Oracle).** Replacing Qwen2.5-7B-Instruct with Llama-3.1-8B as the oracle while keeping the same world generation and scoring procedure yields **24.5%** accuracy—the highest value across all conditions. This is the opposite of the heterogeneity hypothesis: the same-model oracle *outperforms* the heterogeneous oracle by 3.9 percentage points.\\n\\n**Ablation B (Random Worlds).** Replacing diagnostic world generation with random ground-atom sampling yields **23.0%** accuracy, lower than same-model oracle but above the heterogeneous-oracle main method.\\n\\n**Ablation C (m=4 Worlds).** Reducing world count from 8 to 4 yields **23.5%** accuracy, similar to the m=8 condition.\\n\\nThe pattern across ablations is surprising: the world-probing mechanism in any configuration (same-model, random, m=4) tends to outperform the heterogeneous-oracle design. This suggests that matching the oracle model to the generator's FOL syntax conventions—which NLTK-syntax Llama formulas share more closely with a Llama oracle than a Qwen oracle—is more important than parametric independence at the small-model scale tested here.\\n\\n[FIGURE:fig_ablations]\\n\\n# Discussion\\n\\n## Why HOWP Did Not Confirm the Core Hypothesis\\n\\nThe heterogeneous-oracle main method (20.6%) failed to outperform top-1 generation (19.6%) by the required 5 percentage points (S3), self-consistency by 3 points (S4), or the same-model oracle by 3 points (S5). We attribute this to a cascade of two root causes.\\n\\n*Root cause 1: Low beam recall (38%).* When fewer than half the k=5 beams contain a correct candidate, selection methods are operating on largely incorrect material. Even a perfect selection oracle—one that always picks the correct candidate when one exists—would achieve at most 38% accuracy. The observed methods achieve 20–25%, consistent with imperfect selection over a 38% recall beam.\\n\\n*Root cause 2: Oracle-generator syntax mismatch.* Llama-3.1-8B generates FOL in NLTK logic module syntax. Qwen2.5-7B-Instruct, trained on different corpora and syntax conventions, interprets formulas slightly differently when making world-truth judgments. This syntax mismatch reduces the discriminative value of the cross-world agreement signal precisely for the most nuanced candidates—those with complex quantifier scope or nested implications—which are also the cases where correct selection would be most valuable.\\n\\nThe unexpected superiority of the same-model oracle (24.5%) supports this interpretation: Llama's oracle judgments about its own generated formulas are better calibrated to the NLTK syntax it generates, yielding more accurate cross-world agreement scoring despite the self-consistency concern.\\n\\n## What the Mechanism Got Right\\n\\nThe world-probing mechanism itself functioned correctly. For each of 204 examples, the pipeline generated 8 diagnostic worlds, collected oracle judgments, computed formula truth via the model checker, and selected a candidate based on cross-world agreement [ARTIFACT:art_KBu-e9nf2SfO]. The pilot oracle accuracy of 76.7% demonstrates that Qwen2.5-7B-Instruct can judge sentence truth in minimal worlds with reasonable accuracy. The infrastructure for annotation-free model-theoretic evaluation is sound; the limitation is the generation quality of the small-scale candidate generator, not the selection mechanism.\\n\\n## Implications for the Independence Hypothesis\\n\\nThe ensemble-theory motivation for oracle heterogeneity assumes that intra-model self-consistency bias is the dominant source of error in single-model evaluation. Our results suggest an alternative: when candidate formulas are expressed in syntax learned by model A, model B's judgments about those formulas may be less calibrated than model A's own judgments—even if model A is the generator. The independence benefit requires that calibration accuracy be roughly equal across oracle models; at 7B-parameter scale with different training data, this may not hold. A more careful investigation of cross-model formula interpretation accuracy—analogous to the pilot study for world-truth judgments—is needed before oracle independence can be assumed beneficial.\\n\\n## Limitations\\n\\n1. **Scale**: Both generator and oracle are 7–8B parameter models. The heterogeneity benefit may emerge at larger scales where models are more uniformly calibrated to formal syntax.\\n2. **FOLIO difficulty**: FOLIO premises involve complex multi-hop reasoning chains with 3–8 premises per problem. The per-sentence world-probing approach selects each sentence's FOL translation independently, ignoring inter-premise consistency, which limits its advantage over top-1 generation.\\n3. **Beam recall ceiling**: The 38% oracle upper bound from Llama-3.1-8B makes it impossible to evaluate the selection mechanism's ceiling performance. Future experiments should verify beam recall ≥60% before attributing selection failures to mechanism design.\\n4. **Single benchmark**: We evaluate only on FOLIO. The hypothesis about closed-world sentences with named-domain quantifiers may hold more cleanly on benchmarks like ProofWriter or synthetic datasets with simpler scoping.\\n5. **Oracle judgment noise**: At 76.7% pilot accuracy, the oracle introduces substantial noise into the cross-world agreement signal. With m=8 worlds and ~23% oracle error rate, agreement scores have high variance, reducing discriminative power.\\n\\n# Conclusion\\n\\nWe presented HOWP, the first annotation-free world-probing pipeline for NL-to-FOL candidate selection, and evaluated it rigorously on 204 FOLIO validation examples. The core heterogeneity hypothesis—that model-family independence between generator and oracle produces better selection than same-model evaluation—was not confirmed: the same-model oracle ablation achieved 24.5% vs. 20.6% for the heterogeneous design. The dominant finding is that beam recall (38% for Llama-3.1-8B at k=5) is the binding constraint on any selection-based method; with under 40% of beams containing a correct candidate, selection improvements are second-order effects.\\n\\nThese results reframe the problem. Future work should:\\n- Use a stronger generator (e.g., Llama-3.1-70B or GPT-4o) and verify beam recall ≥60% before evaluating selection mechanisms.\\n- Investigate cross-model FOL syntax calibration before assuming oracle independence is beneficial.\\n- Explore premise-set-level selection that maintains inter-sentence consistency rather than selecting each sentence independently.\\n- Test on simpler benchmarks with explicit named-domain quantification where the closed-world assumption is unambiguous.\\n\\nThe HOWP infrastructure—world generator, symbolic model checker, cross-world scoring—is sound and reusable.
